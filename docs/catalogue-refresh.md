# Shared catalogue refresh

Catalogue managers (`Authorization:CatalogueManagerUserIds`) can refresh the entire shared catalogue from Settings → Database. The confirmation shows the current book count. Both status and submission endpoints require the existing `ManageCatalogue` policy; personal reading data is never loaded or modified by the refresh worker.

The batch snapshots book IDs and titles, persists an outcome for each entry, and keeps the latest report available at `GET /api/catalogue-refresh`. A unique nullable active-slot index prevents overlapping batches. Workers acquire a three-minute database lease, process one book at a time, and release it after each item. Each fetch has a 90-second deadline. A crashed instance's lease expires, allowing another instance to resume. Before saving, a short database transaction verifies the current lease owner and expiry; a stalled worker whose lease was reclaimed discards its changes. Metadata and item progress save atomically; interrupted items can be retried. A two-second interval limits load, in addition to the existing provider controls.

ISBN is the edition identity. Refresh uses the existing metadata and cover fetcher priority configuration; a different returned ISBN is a per-book failure. Entries without ISBN resolve their persisted external edition references through active search providers, without guessing an edition by title. An entry with neither a valid ISBN nor a resolvable reference, or unavailable metadata, produces “No update available”. A failed cover does not prevent metadata updates. Valid existing values survive blank or missing provider values. Nonblank title, subtitle, publisher, publication date, genres, collection, additional metadata and successful covers may be enriched; existing author associations are retained and missing author photographs use the same enrichment as imports. User books, shelves, reading states/dates, ratings, comments and favourites remain untouched.

For linked editions without ISBN, year-only provider dates do not replace an existing precise publication date, and existing cover bytes are retained. ISBN refreshes can replace covers only with a successful nonempty image and MIME type. Provider faults are recorded as failures when no fallback succeeds; ordinary empty results and identical metadata count as no update available.

The report counts successful updates, entries with no update available, and failures with book IDs and titles. Failures do not stop later entries. Restart recovery is bounded by the lease duration. The latest report is shown again when reopening settings; prior reports remain in the database.
