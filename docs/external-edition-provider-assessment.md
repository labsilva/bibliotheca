# External edition provider assessment

## Catalogue sample

On 21 November 2026, ten books were drawn at random from the local catalogue,
among records with an ISBN and at least one author. Each query used the catalogue
title and first author. A result counted as an exact edition when its ISBN
matched the catalogue ISBN after ISBN-10 to ISBN-13 conversion. Positions are
one-based. Latency includes search, edition lookups and request pacing. Use
the same private sample for every provider. The figures below are aggregate
results from this sample.

| Provider | Exact editions | Extra exact editions beyond Open Library | Median latency | Evidence |
| --- | ---: | ---: | ---: | --- |
| Open Library | 3/10 | — | 1.96 s | Live. All three exact editions ranked first. No API errors. |
| Google Books | Deferred | Deferred | Deferred | Search and lookup verified with HTTP fixtures. A live API key is needed. |
| Hardcover | 3/10 | 0 | 2.09 s | Live GraphQL search and edition lookup. Exact editions ranked 1st, 9th and 13th. No API errors. |
| Wook | 9/10 confirmed | 7 | — | Public product pages, confirmed by ISBN. |
| Bertrand | 8/10 confirmed | 5 | — | Public product pages, confirmed by ISBN. |

The Wook and Bertrand checks used public title-and-author search results, with
targeted ISBN searches to find or verify earlier editions. These counts describe
confirmed catalogue coverage. Search latency, rank and official API coverage
were outside what the public pages could establish. Together the shops had all
ten exact editions.

### Repeating the API comparison

Use PowerShell 7 and an isolated HTTPS Bibliotheca instance. Enable one provider
at a time and keep its API credentials in the backend configuration. Set
`BIBLIOTHECA_BENCHMARK_ACCESS_TOKEN` to a Bibliotheca session access token.
Keep the original sample outside the repository as a JSON array of ten records
with `title`, `author` and `isbn` fields.

```powershell
./scripts/Measure-ExternalEditionSearch.ps1 -ApiBase https://localhost:5501 `
  -ProviderId openLibrary -SamplePath $sample | Set-Content $baseline
```

After switching the instance to the next provider, pass the baseline report
with `-BaselinePath $baseline`. The command checks that the sample is identical
and reports exact-edition ranks, additional matches, median latency and failed
queries without including the book records or tokens. For an end-to-end latency
comparison, use the report generated by this command as the baseline. The
original Open Library figure above was measured directly against the provider.

## Provider decisions

### Open Library (#21)

Use its Search API to identify up to three relevant works and its Works and
Editions APIs for edition-level metadata and lookup. The anonymous
benchmark paced calls at roughly one per second. With an installation contact
configured, the application identifies itself and uses the documented higher
request allowance. See [Search API](https://openlibrary.org/dev/docs/api/search),
[Book APIs](https://openlibrary.org/dev/docs/api/books) and
[API usage limits](https://openlibrary.org/developers/api).

### Google Books (#22)

The adapter uses volume search by title and optional author and retrieves a
specific volume by ID. The anonymous request returned HTTP 429 in both the
original trial and the current check.
The Books branding guidance calls for Google attribution, prominent result
links and preservation of Google result order. The general API terms also
restrict permanent copies and caching unless permitted by the content owner or
applicable law. The current federated display merges editions by ISBN, and
the catalogue retains imported metadata. Keep the provider disabled for this
workflow until permission for that usage is established, or design a separate
Google display that follows the published terms. See the
[Books API guide](https://developers.google.com/books/docs/v1/using),
[branding requirements](https://developers.google.com/books/branding) and
[API terms](https://developers.google.com/terms#e-prohibitions-on-content).

### Hardcover (#23)

The authenticated live run used the same ten books and the adapter's GraphQL
queries. The three exact ISBN matches were the same three found by Open Library.
Lookup by edition ID returned the title, ISBNs, language, format, publisher and
cover metadata. Search latency includes pacing between GraphQL calls.

The adapter searches ranked book IDs and resolves their editions through
GraphQL. It uses a scoped server-side token and reads public catalogue fields.
The Free plan documents 5,000 daily requests and 60 per minute, with a burst
allowance. Each top-level GraphQL field counts separately, so a search with
edition results costs two requests. Hardcover disclaims ownership of the
public catalogue data and calls out that user-uploaded images can carry
third-party rights. The catalogue retains the cover URL. Public displays using
those images should follow Hardcover's takedown guidance. See the
[API guide](https://raw.githubusercontent.com/hardcoverapp/hardcover-docs/main/src/content/docs/api/Getting-Started.mdx),
[edition schema](https://raw.githubusercontent.com/hardcoverapp/hardcover-docs/main/src/content/docs/api/GraphQL/Schemas/Editions.mdx)
and [Hardcover policies](https://hardcover.app/pages/policies).

### Goodreads (#24)

Goodreads stopped issuing new developer keys in December 2020 and announced
plans to retire the public API. The GitHub issue records that public pages
surfaced editions absent from Open Library, while previous Playwright requests
returned 202 without data or 403, including ISBN searches. An authorized,
stable route for a new integration was not established. See the
[official developer announcement](https://www.goodreads.com/group/show/8095-goodreads-developers).

### Amazon (#25)

The issue's earlier public-page benchmark confirmed 8 of 10 editions across
Amazon.es and Amazon.com. It used a different sample. Creators API provides
SearchItems for Associates. Amazon requires driving Amazon sales to be the
application's primary purpose, prohibits storing product images and limits
caching of other API content. Permanent import into a household catalogue is
incompatible with those standard terms. See
[SearchItems](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/api-reference/operations/search-items)
and the [Associates license](https://affiliate-program.amazon.com/help/operating/policies).

### Wook (#26)

The application already uses Wook for ISBN enrichment. Its published affiliate
programme covers links and approved promotion. The public documentation
review did not establish an authorized title and author API or feed with
permission to retain edition metadata. Nine exact editions were confirmed in
its public catalogue, seven that Open Library did not return. See
[Wook's affiliate terms](https://www.wook.pt/Afiliados).

### Bertrand (#27)

The application already fetches Bertrand covers by ISBN. Bertrand publicly
documents a community and affiliate programme. The public documentation review
did not establish an authorized API or feed for title and author lookup and
persistent storage of Portuguese editions. Eight exact editions were confirmed
in its public catalogue, five that neither Open Library nor Hardcover returned. See the
[Bertrand affiliate programme](https://www.bertrand.pt/online/afiliados).

### ISBNdb (#28)

The existing cover fetcher does not provide credentials or permission for a
metadata subscription. The official pricing, FAQ, terms and API documentation
returned HTTP 403 from this environment. The unauthenticated metadata
endpoint returned HTTP 401. Price, quota and the conditions for
storing metadata and covers remain unverified. An authorized subscription with
terms compatible with catalogue retention is required to run the comparison.
ISBNdb advertises a seven-day Basic trial in its [company profile](https://www.linkedin.com/company/isbndb).
See the [provider's API documentation](https://isbndb.com/isbndb-api-documentation-v2),
[subscription plans](https://isbndb.com/isbn-database) and
[terms and conditions](https://isbndb.com/terms-and-conditions).
